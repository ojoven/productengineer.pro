## Why it matters for a product engineer

The first screen after signup is often an empty product: no data, no projects, nothing to look at.
The new user then has to guess what to do. Designing that first run on purpose, with a clear first
task, sample data or a template, decides whether people see value or leave. It is also code: seed
data, templates and empty states must be built, and kept up to date as the product changes.

## How to do it

1. Write down the first useful thing a new user can do, and design the first screen around it.
2. Replace blank panels with empty states that say what will appear there, and how to fill them.
3. Next to the path with real data, offer a safe way to explore, such as demo data or a template.
4. Do not show loading content as "no items". Say when the system is still working.
5. Watch a few new users go through the first run, and instrument where they stop.

## Common mistakes

- An empty dashboard with no next step.
- Demo data that is hard to remove, or mixed with real data.
- A "No results" message while the data is still loading.
- A first run designed once and never checked again.

## Example

NN/g describes Loggly, a cloud tool for managing logs. A new account has no logs yet, so its empty
state offers two direct paths: add real log sources, or load demo data and explore safely. In
Datadog, an empty favourites panel says "Star your favorites to list them here", which explains both
the feature and the purpose of the space.
